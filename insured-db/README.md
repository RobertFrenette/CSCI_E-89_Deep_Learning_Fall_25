## AI Agent Insure — insureds.db

## Overview

`insureds.db` is a local SQLite database containing **fictional, internally structured insurance data** for use with the AI Agent Insure RAG system.

It is designed to support RAG + SQL hybrid retrieval for various insurance-related use cases, including:

- Customer Service Agent queries
- Underwriting assistance
- Claims lookup
- Risk assessment

This database is **file-based**, requiring no server setup.  
It can be used directly with Python, LangChain, and the local RAG pipeline.

## Database Schema

The database contains **five tables**, linked by shared keys (`Insured_ID`, `Policy_Number`).  
The structure simulates a realistic insurance data model.

### 1. insureds (100 records)

Core customer information (PII + demographic + business data).

- **Primary Key**: `Insured_ID`
- **Columns**: First_Name, Last_Name, Date_of_Birth, Phone_Number, Email_Address, Address_Line1, Address_Line2, City, State, Postal_Code, Country, Company_Name, Industry, Contact_Person

### 2. policies (208 records)

1–3 policies per insured. Represents the master policy list.

- **Primary Key**: `Policy_Number`
- **Foreign Key**: `Insured_ID` → `insureds.Insured_ID`
- **Columns**: Policy_Type, Effective_Date, Expiration_Date, Policy_Status, Payment_Status, Annual_Premium, Monthly_Premium, Payment_Method, Broker, Discounts_Applied

### 3. coverage_details (208 records)

Coverage configuration for each policy.

- **Primary Key**: `Policy_Number`
- **Foreign Key**: `Policy_Number` → `policies.Policy_Number`
- **Columns**: Coverage_Limit, Deductible, Coverage_Tier, Optional_AddOns_Selected, Regulatory_AddOns_Selected, Business_Interruption_Coverage, Cyber_Extension, Incident_Response_AddOn

### 4. ai_risk_profile (208 records)

AI footprint + underwriting risk attributes.

- **Primary Key**: `Policy_Number`
- **Foreign Key**: `Policy_Number` → `policies.Policy_Number`
- **Columns**: AI_System_Type, Deployment_Stage, Number_of_Active_Agents, Critical_Workflows_Protected, Incident_History_Count, Last_AI_Incident_Date, Has_High_Risk_Use_Cases, Regulatory_Classification, Risk_Score_Internal

### 5. claims_history (46 records)

AI-related claims associated with each insured.

- **Primary Key**: `Claim_ID`
- **Foreign Keys**: `Policy_Number` → `policies.Policy_Number`, `Insured_ID` → `insureds.Insured_ID`
- **Columns**: Claim_Date, Claim_Type, Claim_Description, Claim_Status, Claim_Amount, Amount_Paid

## Relationships

- insureds → policies (Insured_ID)
- policies → coverage_details (Policy_Number)
- policies → ai_risk_profile (Policy_Number)
- policies → claims_history (Policy_Number, Insured_ID)

## Creating/Rebuilding the Database

### Script: `create_and_seed_insureds_db.py`

**A development/setup utility** that creates and populates the SQLite database from CSV files.

**Purpose**: Converts the CSV files in `./insured_data/` into a properly structured SQLite database with foreign key relationships. This is a one-time setup tool - the RAG application reads from the resulting `insureds.db` file and does not require this script to run.

**Usage**:

```bash
python create_and_seed_insureds_db.py
```

**What it does**:

1. Delete existing database file (if it exists) for a clean start
2. Create new database with schema and foreign key constraints for 5 tables:
   - insureds
   - policies
   - coverage_details
   - ai_risk_profile
   - claims_history
3. Import all CSV data from `./insured_data/` in correct order (respecting foreign keys)
4. Create indexes for query performance
5. Verify the import with statistics and show sample queries

**Output**:

- SQLite database: `insureds.db` (136KB)
- 770 total records across 5 tables

**Requirements**:

- Python 3.x (standard library only - no external dependencies)
- CSV files in `./insured_data/` folder:
  - insureds.csv
  - policies.csv
  - coverage_details.csv
  - ai_risk_profile.csv
  - claims_history.csv
